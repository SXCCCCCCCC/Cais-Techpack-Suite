# 终局流程设计

产物主线：**远古奖杯残片 → 粉碎 → 浸洗 → 深加工 → 组合 → 雕琢 → 模具 → 模具水晶 → 金猪浇铸 → 冷却 → 炸洗 → 剪水口 → 表面处理 → 充能 → 金奖杯**

本流程由用户于 2026-09-15 设计。本文是设计原稿的整理版，附带**每台机器属于哪个上游**的映射，
用来决定 `libs/` 需要接哪些 API。

## 0. 实现方式的分工（重要）

流程里的 15 步，绝大多数不是 Java 代码，而是**配方数据**：

| 层面 | 内容 | 落在哪 |
|---|---|---|
| 配方数据 | 「X 机器 + A + B → C」这类条目（GT 化学浸洗机、Create 注液、IE 灌装机、Mek 化学溶解室、Thermal 结晶器、PNC 压力室、AE2 熵变机械臂……） | KubeJS / datapack（**不需要 Java**） |
| 掉落注入 | 各采矿机器按概率出「远古奖杯残片」 | 战利品表 / KubeJS 配方 |
| 新内容 | 残片、各级中间物、金猪流体、各种模具、奖杯 | Java（注册 + 资产 + lang） |
| 特殊交互 | 第 11 步「放地上五分钟」「放背包里 3600s」、第 14 步「背包里自然风化」、第 5 步爆炸合成 | Java（tick / 放置计时 / 事件） |
| 充能 | 第 15 步跨 mod 能量 capability（FE / EU / J / AE / RF / SU / GEF） | Java（**这一步才是真正要接一堆上游 API 的地方**） |

也就是说：**Java 侧真正需要 compileOnly 上游 API 的，主要是第 15 步与少量特殊交互**；
其余步骤即使不接 API 也能走 KubeJS 完成。`libs/` 里仍然全接了，是为了后面写 Java 时不受限。

## 5. 组合

> 这一步就是故意卡你：做了神秘农业就不要堆量，没做就只能攒 25 个。

| 路线 | 上游 | 方式 |
|---|---|---|
| 物理法 | Create | 25 个残片合成「有点轮廓的奖杯」 |
| 魔法法 | Mystical Agriculture（+ Agradditions） | 祭坛：各 40 四种元素精华 + 四个残片 + 中心一个究极精华块 |

设计意图：反质子路线成本过高不可行；其他路线至少要搭样版产线；发展了神秘农业则不必堆量。

## 7. 做模具

> 我们只能做个模具，来复刻它。

| 路线 | 上游 | 代价 |
|---|---|---|
| 沙 | — | 沙子工作台合成，**消耗**产品 → 坑坑洼洼的模具（沙） |
| 蜡 | 资源蜜蜂（Productive Bees） | 八个蜜蜡围一圈，**不消耗**产品 → 坑坑洼洼的模具（蜡） |
| 完美 | IU 或 GTCA | IU 质子丸 / 质子核心按 `WHW / HJH / WHW`（非常贵）；或 GTCA 质子 8 个围一圈（成本低但机器极难）→ 完美模具，**消耗**产品 |

## 8. 坑坑洼洼的产品处理

> 尽管模具坑坑洼洼，但用机器仍然可以辨识出东西。

1. 二氧化硅粉 + 黑曜石粉，`WHW / HJH / WHW` → 粗制完美模具水晶
2. 熔炉烧炼 → **模式存储水晶（带完美模具 NBT）**
3. 可走 IU 或 IC2 的 UU 复制线：消耗 1mB UU 物质 → 完美模具
